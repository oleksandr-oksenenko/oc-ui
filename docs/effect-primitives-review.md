# Higher-level Effect primitives

Inventory of application lifetime and concurrency code against Effect `4.0.0-rc.112`. The review covers `apps/desktop/src`; SDK internals, DOM behavior, and generated code remain outside the migration. Graph transport was unavailable, so discovery and verification used source reads and installed Effect implementation.

## Completed replacements

| Area                                      | Previous handling                                                                          | Replacement                                                                                                                                                                         |
| ----------------------------------------- | ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Forms and agent selection                 | Manually rotated child scopes, explicit closure, read fiber fields, and scope-state checks | Scoped read workflows through the shared `latest()` adapter; selection identity only controls whether mutation errors are still relevant.                                           |
| Directory browser and selected transcript | Separate mutable request fibers and interruption helpers                                   | The same `latest()` adapter. Replaced requests remain workspace-owned until native I/O settles.                                                                                     |
| Workspace callback boundary               | Created another child scope and accepted arbitrary scopes for each fork                    | Uses its supplied scope and `forkScoped`; `runSync` acquires scoped built-ins in that lifetime. One `FiberMap` tracks current reads without retaining completed controller entries. |
| Connection resources                      | Explicit workspace scope closure and a mutable Solid disposer                              | `ScopedRef` owns replacement/disposal; `acquireRelease` owns the Solid root. Resource acquisition order makes work settle before disposing the SDK store.                           |
| New/Delete Session dialogs                | Status atoms pinned until disconnect                                                       | Scoped mount acquisition returns a release callback. Completed/dismissed flows release state after mutation cleanup; view remounts retain the controller.                           |
| Session creation partial completion       | Ordinary error handling skipped interrupted requests                                       | A scoped finalizer reconciles the settled SDK response and reports a retained worktree when session creation failed.                                                                |
| Transcript queue workers                  | Permanent map entry and worker for each visited session                                    | `RcMap` leases retain a FIFO queue through every submitted job, then release the idle worker.                                                                                       |
| Catalog and model refresh                 | Mutable in-flight fibers and completion checks                                             | `cachedWithTTL(..., 0)` shares running refreshes and expires their result after settlement, allowing explicit subsequent refreshes.                                                 |
| VCS reads                                 | Manually maintained active-fiber map                                                       | `FiberMap` removes completed entries. The workspace separately retains interrupted native I/O.                                                                                      |
| Catalog and VCS subscriptions             | Manual finalizer registration or relying on event-source disposal                          | `acquireRelease` pairs registration and unsubscription.                                                                                                                             |
| Reconnect refresh                         | Manual forever/take loop                                                                   | `Stream.fromQueue`, filtering connected transitions and consuming them sequentially.                                                                                                |
| Settings worker                           | Explicit `forkIn` with the current scope                                                   | `forkScoped`.                                                                                                                                                                       |
| OpenCode utility worker                   | Manually acquired/provided nested scope                                                    | The existing outer `scoped` region, with shutdown signaling in `ensuring` before resource release.                                                                                  |

## Deliberately retained

- **Settings request scope and Queue:** shutdown must reject new jobs, discard pending jobs, interrupt active requests in parallel, and await native settlement. A generic serial semaphore does not implement that policy.
- **Local server ownership:** shared startup survives individual caller cancellation. Failed termination retains the child so a later explicit Quit can try again; a one-shot resource finalizer cannot replace that behavior.
- **Connection transition ordering:** replacing an attempt interrupts it and awaits its cleanup before starting the next transition. The short fiber chain preserves that ordering across repeated replacements; `ScopedRef` owns the workspace resource separately.
- **Native Promise adapters:** Electron IPC and some SDK helpers cannot cancel their actual work. The adapter must retain ownership until the Promise settles. `tryPromise` alone does not supply that guarantee.
- **Callback Deferreds:** worker commands, SDK handshake, initial-sync barriers, and early shell-exit events need completion delivered from another callback or workflow. A fresh Effect description is not shared completion.
- **Application state and rules:** catalog event replay, mutation admission, selection identity, stop exclusion, SDK caches, and partial-completion decisions are not redundant coordination. No SDK helpers/stores were replaced and no automatic retries were added.
- **DOM listeners and focus timers:** Solid/browser lifetimes remain appropriate for pointer interaction and focus restoration.

## Verification

Focused regressions cover selection replacement overlapping shutdown, stale mutation errors after returning to a prior selection, dialog mount release, interrupted session creation, idle transcript worker release, shared refreshes after failure, and reconnect transitions. Full repository checks/tests and packaged Electron acceptance validate the combined change; their final result is recorded in the accompanying task response.
